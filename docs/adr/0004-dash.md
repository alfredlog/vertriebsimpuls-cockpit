# ADR 0004: Plotly Dash with Tailwind (Play CDN) for the cockpit

- Status: accepted
- Date: 2026-11-27
- Code: `app/`

## Context

Sales reps need a daily list with reasons, a client view, a market view and a
monitoring page; feedback ("angenommen" / "abgelehnt") must be written back. The
project is Python end to end and maintained by one person; the UI should be
testable with pytest and run locally with one command.

## Decision

- **Plotly Dash** (multi-page with `dash.register_page`), Plotly for charts,
  `dash_table.DataTable` for tables (AG Grid is not a dependency).
- **Tailwind CSS via the official Play CDN** for layout and styling; one shared
  Plotly template for all charts.
- All data access goes through `app/data.py`, which only uses `vic.db` helpers;
  one DuckDB connection behind a lock, because Dash serves requests from several
  threads.
- Callbacks stay small: filter, feedback, empty state, shell display, client
  picker; none writes data except the feedback callback, none is circular.
- Entry point `uv run python -m app`; debug off, host/port from environment
  variables.

## Consequences

- Pages and callbacks are plain Python functions: tests render every layout and
  call the feedback callback directly, without a browser.
- `dash_table.DataTable` is deprecated in Dash 4 (to be removed in a future major
  version); a migration to `dash-ag-grid` is a separate step. The warning is
  filtered in pytest by exact message only.
- The Tailwind Play CDN is meant for development: it needs internet access at
  runtime and generates CSS in the browser. For a bank network (CSP, no external
  requests) Tailwind must be built at deploy time (Tailwind CLI) and served as a
  static file.
- Single user: DuckDB allows one writing process per file, so the app and the
  daily pipeline cannot hold the same file at the same time.

## Alternatives considered

- **Streamlit:** faster for prototypes, but the rerun-on-every-interaction model
  makes per-row feedback buttons and multi-page state awkward.
- **React/Next.js + FastAPI:** the most flexible UI, but two languages, a build
  chain and much more code for a one-person project.
- **Power BI / Tableau:** strong for reporting, but writing feedback back and
  versioning the logic in Git are limited.
